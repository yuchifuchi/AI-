# 07 本番環境を「一から」作る（中学生でもわかる・セキュリティ込み）

このマニュアルは、**本番用の環境をゼロから作り直す**ための“通し”手順です。
これまでの `01`〜`06` を土台に、**今回強化したセキュリティ（画面ログイン・IP制限・暗号化など）**を
最初から組み込んだ状態で作ります。

> 読む順番：**この07を「地図」**として上から進めます。細かいAWSのクリック手順は `01`、munu設置の細部は `02`、
> HTTPS化は `06` を都度参照します（同じことを二重に書かないため）。
>
> できあがると：**ログインした社内の担当者だけ**が、暗黙知と公式マニュアル（PDF/Word/Excelも）を
> AIに質問でき、データは**暗号化された非公開のAWS**に置かれ、**mintの拠点からしか**呼び出せません。

---

## 0. 全体像（何を作るか・1枚）

```
[社内PC(ログイン必須)] --HTTPS(将来)--> [munu(IIS/ASP)] --HTTPS + 秘密ヘッダ + IP制限--> [Lambda] --(実行ロール)--> [非公開S3(KMS暗号化) / Bedrock KB]
        ↑ ACCESS_PASSWORD / ADMIN_PASSWORD で画面ログイン          ↑ RELAY_KEY / ADMIN_OP_KEY        ↑ Block Public Access ON・バージョニングON
```

**今回の“守り”は大きく2つ（A：コード、B：AWS設定）。どちらも他部署なしで完結します。**

| 区分 | 何を | どこで |
|---|---|---|
| **A. コード（済・このリポジトリ）** | 質問/登録画面にログイン、機微内容のキャッシュ抑止、原本ファイルのサイズ上限、一括投入 | munuにファイルを置くだけ |
| **B. AWS設定（あなたがコンソールで）** | 送信元IP制限、SSE-KMS暗号化、バージョニング、CloudTrail、鍵ローテ | AWSコンソール |

> HTTPS化（証明書）だけは情シス依頼が要ります（§8）。それ以外はあなただけで完了できます。

---

## 1. 準備するもの

- **AWSアカウント**（Bedrock/Lambda/S3を作れる権限）。リージョンは **東京（ap-northeast-1）**。
- **munu（IIS + classic ASP）** にファイルを置ける手段（FTP・共有フォルダ・リモートデスクトップ等）。
- **社内プロキシのIP:PORT**（munuからAWSへ出るため。例 `10.33.2.33:8080`）。
- **mintの“出口”グローバルIP**（AWSから見た送信元。§5で使う。分からなければ後述の調べ方）。
- テキストエディタ（**VSCode推奨**。UTF-8 BOMなしで保存できるもの）。

## 2. まず「鍵」と「パスワード」を4つ用意する

コピペで使い回すので、先に**メモ帳などに4つ**作っておきます（画面には出さない・安全な場所に保管）。

| 名前 | 用途 | 作り方の目安 |
|---|---|---|
| `RELAY_KEY` | munu↔Lambda の合鍵① | 英数字32桁以上のランダム |
| `ADMIN_OP_KEY` | 管理操作の合鍵②（①とは別） | 英数字32桁以上のランダム |
| `ADMIN_PASSWORD` | 管理画面ログイン（人が打つ） | 推測されにくい長い文字列 |
| `ACCESS_PASSWORD` | 質問/登録画面ログイン（利用者に配る） | 推測されにくい長い文字列（①②や管理PWと別） |

> 💡 ランダム鍵の作り方（どれでも可）：
> - PowerShell：`[Convert]::ToBase64String((1..32|%{Get-Random -Max 256}))`
> - ブラウザのアドレス欄で `javascript:` は使わず、パスワード管理ツールの「生成」機能でもOK。
> - **①②は必ず別の値**。1文字でも違うと `unauthorized`/`admin_forbidden` になります。

## 3. AWS：S3バケット（非公開＋暗号化＋バージョニング）

`01_aws_setup.md` のバケット作成手順をベースに、**本番では次の3点を必ず**設定します。

1. **Block Public Access：4項目すべて ON**（公開を完全に断つ）。
2. **バージョニング：有効**（誤削除・上書きから復元できる）。
   - コンソール：対象バケット →「プロパティ」→「バケットのバージョニング」→**有効化**。
3. **既定の暗号化：SSE-KMS（顧客管理鍵 CMK）**。
   - 先に **KMSキーを作成**：KMS →「カスタマー管理型のキー」→ 作成（対称・暗号化）。
     - 別名（エイリアス）例：`alias/munu-kb`。
     - **キーの管理者**とキーポリシーは最小限に（触れる人を絞る）。
   - バケット →「プロパティ」→「デフォルトの暗号化」→ **SSE-KMS** → 上のCMKを選択。
   - **バケットキーを有効**（KMS呼び出しコスト削減）。

> ✅ こうなれば成功：バケットが「公開なし・バージョニングON・SSE-KMS」の3点になっている。
> ⚠️ 既存の環境から作り直す場合、**古い公開バケット（Plan C由来）は使わない**。新規で非公開バケットを作ること。

---

## 4. AWS：Bedrock KB・Lambda・Function URL

ここは `01_aws_setup.md` の手順どおりに作成します（変更なし）。ポイントだけ：

1. **Bedrock ナレッジベース（KB）** と **データソース（上のS3バケット／プレフィックス `tacit/`）** を作成。
   - ベクトルストア（OpenSearch Serverless 等）も**暗号化・最小権限**で作成（作成時の既定でOK。触れる人を絞る）。
   - **原本ファイル（PDF/Word/Excel/CSV/HTML）を使う**ので、データソースの解析は既定（テキスト抽出）でOK。
     スキャン画像だけのPDFを使うなら、KBの**「高度な解析（パーサ）」を有効化**（別料金・OCR相当）。
2. **Lambda関数**（`munu-kb-routeb`）を作成し、`aws/lambda_routeb.py` の中身を貼り付け。
3. **Function URL** を作成（認証タイプ **NONE**）。→ 末尾スラッシュ付きURLを控える（`RELAY_URL`）。
   - ※API Gatewayは社内プロキシを通らないため使いません（Function URLはプロキシ疎通済み）。
4. **実行ロールのIAMポリシー**は `aws/lambda_iam_policy_routeb.json` を使用。
   - **SSE-KMSにしたので、`KbBucketKmsEncryption` の `Resource` を §3で作ったCMKのARNに置き換える**
     （`arn:aws:kms:ap-northeast-1:＜アカウントID＞:key/＜キーID＞`）。SSE-KMSを使わないならこのブロックは削除。

> ✅ こうなれば成功：Function URL が発行され、実行ロールが「対象バケット＋KMS＋KB＋モデル＋ログ」に限定されている。

## 5. AWS：Lambda環境変数（★セキュリティの要）

`aws/lambda_env.example.json` を見ながら、Lambdaの「設定 → 環境変数」に入れます。**本番で特に重要なのは `ALLOWED_IPS`**。

| 変数 | 入れる値 | 備考 |
|---|---|---|
| `KB_ID` / `DATA_SOURCE_ID` / `KB_BUCKET` / `MODEL_ARN` | 各実値 | §4で作ったもの |
| `RELAY_KEY` / `ADMIN_OP_KEY` | §2の鍵①② | munuと**完全一致** |
| **`ALLOWED_IPS`** | **mintの出口グローバルIP**（例 `203.0.113.10/32`。複数可・カンマ区切り） | **本番は必ず設定**。ここ以外からは `403`。＝公開URLでも“mintからしか叩けない”状態にする |
| `MAX_SENSITIVITY` | `mid`（既定） | 機微度ゲート |
| `MAX_BULK_ITEMS` / `MAX_FILE_BYTES` | 既定でOK | 一括投入の上限 |

> 🔎 **mintの出口IPの調べ方**：munu（またはmint内のPC）から `https://checkip.amazonaws.com` を開くと出るIPが「AWSから見た送信元」。
> 分からなければ最初は**空のまま**でも動きます（鍵で守られる）が、**本番稼働までに必ず入れる**こと。
> ⚠️ プレースホルダ文字列（`203.0.113.10/32` のような例のまま）を入れると**全部 forbidden** になります。実IPで。

## 6. AWS：監査の証跡（CloudTrail）

「誰がいつS3のデータを触ったか」を残します。

1. **CloudTrail** →「証跡の作成」。証跡用のログ保存バケットを指定（KBバケットとは別に）。
2. **データイベント**を有効化 → **S3** → 対象を **KBバケット**にして Read/Write を記録。
3. （Lambda側の操作ログは既に CloudWatch に構造化JSONで出ています＝`register`/`ask`/`admin`/`register_bulk`/各種 `deny_*`。）

> ✅ こうなれば成功：KBバケットへの読み書きが CloudTrail に残る。

## 7. munu：ファイルを置く（本番は「8ファイル」）

`02_munu_install.md` をベースに、**本番では次の8ファイル**を munu の `…/tacit2/` に置きます。

| ファイル | 役割 | 秘密か |
|---|---|---|
| `kb_config.asp` | **本物の設定（これから作る）** | ★はい（合鍵・パスワード入り。厳重管理） |
| `kb_lib.asp` | 共通部品（通信・ログイン・JSON・CSRF） | いいえ |
| `kb_ask.asp` | AI質問・会話画面（**ログイン必須**） | いいえ |
| `kb_register.asp` | 気づき登録（**ログイン必須**） | いいえ |
| `kb_admin.asp` | 管理（編集・削除・種別表示） | いいえ |
| `kb_bulk.asp` | 公式マニュアル一括投入（PDF/Word/Excel対応） | いいえ |
| `kb_style.css` | 画面デザイン（これが無いと画面が“素のHTML”に） | いいえ |
| `web.config` | サイズ上限8MB＋保護ヘッダ（**HTTPS化後に有効化する行はコメント済**） | いいえ |

### 手順
1. `kb_config.example.asp` を **`kb_config.asp`** という名前でコピーし、次の**6か所**を本物の値に置換：
   `RELAY_URL` / `RELAY_KEY` / `ADMIN_OP_KEY` / `RELAY_PROXY` / `ADMIN_PASSWORD` / **`ACCESS_PASSWORD`**（§2で用意）。
2. すべて **UTF-8（BOMなし）** で保存（メモ帳のUTF-8はBOM付きになりやすいので**VSCode推奨**）。
3. 上の**8ファイル**を `tacit2/` に置く（`kb_config.example.asp` は置かなくてよい）。

> 🔒 `kb_config.asp` は合鍵入りの秘密ファイル。GitHub等に上げない（`.gitignore`済）。可能ならWebルート外へ。
> ⚠️ `web.config` の中の **`keepSessionIdSecure` と HSTS はコメントのまま**にしておく（HTTPS化が済むまで有効化しない。HTTPで有効化するとログインできなくなる）。

## 8. HTTPS化（情シスに“証明書1枚”だけ依頼）

**社内LAN区間（ブラウザ↔munu）の平文をなくす**ため、munuをHTTPSにします。手順は `06_munu_https.md`。

- 依頼するのは基本 **「munuサーバ用のサーバ証明書（CN=munuのホスト名）」1枚**（社内CA発行が第一候補）。
- 証明書が入ったら：IISに取り込み → **443バインド追加** → **HTTP→HTTPSリダイレクト** → 動作確認。
- **HTTPS化が終わったら**、`web.config` の次の2行のコメントを外す：
  - `<session keepSessionIdSecure="true" />`（セッションCookieをSecureに）
  - `<add name="Strict-Transport-Security" ... />`（常時HTTPS＝HSTS）

> ⚠️ 順番厳守：**先に443バインド／リダイレクトを効かせてから**、上の2行を有効化。逆にすると閉め出します。
> HTTPSが済むまでは、ログインパスワードも社内区間で平文になります（他の画面も同条件）。だから**HTTPS化は早めに**。

## 9. 動作確認（この順で全部通ればOK）

社内PCから開きます（URLは引き継ぎ資料のもの。HTTPS化後は `https://`）。

1. **質問：** `.../tacit2/kb_ask.asp`
   - **ログイン画面が出る**こと（＝無認証で機微が引けない）。`ACCESS_PASSWORD` でログイン → チャットが表示。
   - 「テストです」と質問 → 数秒でAIの回答が出れば成功。
2. **登録：** `.../tacit2/kb_register.asp`
   - ログイン状態のまま開ける。タイトル/本文を入れて登録 → 「登録できました🎉」。
3. **管理：** `.../tacit2/kb_admin.asp`
   - `ADMIN_PASSWORD` でログイン → 一覧（「種別（公式/暗黙知）」列あり）。1件編集/削除で「✅ …しました」。
4. **公式一括投入：** `.../tacit2/kb_bulk.asp`（管理画面の「公式一括投入」からも）
   - `.md/.txt` に加え、**PDF・Word・Excel** を数件選ぶ → プレビュー → 「この内容で公式登録する」→ **「✅ N/N 件」**。
   - 同じファイル名で再投入すると **🔁 更新**（重複せず上書き）。
5. **ログアウト：** 各画面の「ログアウト」→ 再度ログインを求められる。

> ✅ こうなれば成功：**ログインしないと質問できず**、暗黙知・公式（PDF等）がAIで引け、管理・一括投入も動く。

## 10. 本番セキュリティ・チェックリスト（上長にそのまま示せる）

**A. コード（munu側・済）**
- [ ] `kb_ask.asp` / `kb_register.asp` が**ログイン必須**（`ACCESS_PASSWORD`）。
- [ ] `kb_admin.asp` / `kb_bulk.asp` が**管理ログイン必須**（`ADMIN_PASSWORD`）＋Lambda側でも `ADMIN_OP_KEY` 検証。
- [ ] 全画面に**キャッシュ抑止・保護ヘッダ**（`web.config` ＋ SecHeaders）。
- [ ] `web.config` の `maxRequestEntityAllowed=8MB`（原本ファイル投入用）。

**B. AWS（あなたの設定・済）**
- [ ] S3：**Block Public Access ON**／**バージョニングON**／**SSE-KMS（CMK）**。
- [ ] Lambda：**`ALLOWED_IPS` に mint の出口IP**（mint以外は403）。
- [ ] IAM：実行ロールが対象**バケット＋KMS＋KB＋モデル＋ログ**に限定。
- [ ] **CloudTrailデータイベント**でKBバケットの読み書きを記録。
- [ ] 監査ログ（CloudWatch）に操作が構造化JSONで残る（回答本文・秘密値は残さない）。

**C. 情シス依頼（並行）**
- [ ] **munu HTTPS化**（証明書1枚）→ 済んだら `web.config` の Secure/HSTS を有効化。

**D. まだ“未対応”＝上長判断／別案件（正直に）**
- [ ] 本人単位のAD認証（今は共有パスワードで代替）。
- [ ] 公衆インターネットを通さない私設接続（VPN/Direct Connect）。
- [ ] 「機微な業務データをAWSに置いてよいか」のデータ取扱い方針の承認。

> 上長への一言（正確版）：「**診断の重大リスクは対策済み。閲覧も認証必須にし、保存はKMS暗号化・通信はIP制限で mint 限定。HTTPS化だけ証明書を情シスに依頼中**。AD認証・私設接続・データ方針の承認は別途ご判断ください（＝“問題ゼロ”と断言はできないが、既知リスクは管理下）」。

## 11. うまくいかないとき（よくある）

| 症状 | ほぼこの原因 | 直し方 |
|---|---|---|
| どの画面も「ログイン」から進めない | `ACCESS_PASSWORD`/`ADMIN_PASSWORD` 未設定 or 打ち間違い | `kb_config.asp` を確認。UTF-8保存 |
| ログインしても毎回また求められる | （HTTPS化後に）`keepSessionIdSecure` をHTTPで有効化した | HTTPSで開く／リダイレクトを先に効かせる |
| 質問が「認証に失敗（unauthorized）」 | `RELAY_KEY` がAWSと不一致 | 両方を同じ元からコピペ |
| どこからでも「forbidden」 | `ALLOWED_IPS` が実IPでない（例のまま等） | `checkip` で実IPを確認して入れ直す／一旦空に |
| 一括投入でPDFが「送信できない」 | IISの本文上限 | `web.config` の8MB設定を確認。大きいPDFは数件ずつ |
| 画面が“素のHTML” | `kb_style.css` 未設置 | `tacit2/` に置く |
| 日本語が文字化け/500 | UTF-8で保存されていない | 全ASP/CSSを UTF-8（BOMなし）で保存し直す |

## このマニュアルのゴール

- [ ] S3（非公開・バージョニング・KMS）／Lambda（IP制限）／CloudTrail を作った。
- [ ] `kb_config.asp` に6つの値（＋`ACCESS_PASSWORD`）を入れ、8ファイルを `tacit2/` に置いた。
- [ ] 質問・登録・管理・一括投入が、**すべてログイン必須**で動くことを確認した。
- [ ] 情シスに証明書を依頼し、HTTPS化後に `web.config` の Secure/HSTS を有効化した。

これで、**認証・暗号化・IP制限**の3層で守られた本番環境になります。
