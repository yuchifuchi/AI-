# 02 munu設置マニュアル（ファイルを置いて合鍵を設定）

AWS側（`01`）で作った **窓口URL（RELAY_URL）** と **合鍵（RELAY_KEY / ADMIN_OP_KEY）** を、
munu（IIS/classic ASPサーバ）に設定して動かします。

> 所要：30〜45分。munuにファイルを置く方法（FTP・共有フォルダ・リモートデスクトップ等）を用意しておいてください。
> ⚠️ **本番をいきなり置き換えない**方法（無停止・切り戻し可）は `04_移行手順` にあります。初回や不安な場合はそちらの手順で。

---

## 置くファイル（このリポジトリの `munu/` から）

| ファイル | 役割 | 秘密か |
|---|---|---|
| `kb_lib.asp` | 共通部品（窓口呼び出し等） | いいえ |
| `kb_register.asp` | 気づき登録フォーム | いいえ |
| `kb_ask.asp` | AI質問・会話画面 | いいえ |
| `kb_admin.asp` | 管理画面 | いいえ |
| `kb_bulk.asp` | 公式マニュアルの一括投入（管理者用） | いいえ |
| `kb_config.example.asp` | 設定の**見本**（これを元に本物を作る） | いいえ |
| **`kb_config.asp`** | **本物の設定（これから作る）** | **★はい（合鍵入り。厳重管理）** |

設置先フォルダ：munu の **`…/tacit2/`**（引き継ぎ資料の設置場所）。

---

## ステップ1. 設定ファイル `kb_config.asp` を作る

1. `munu/kb_config.example.asp` を**コピー**し、名前を **`kb_config.asp`** に変える。
2. テキストエディタ（メモ帳でも可。おすすめは秀丸/VSCode等）で開き、次の5か所を**本物の値に**書き換える：

| 場所（変数） | 何を入れるか | 例 |
|---|---|---|
| `RELAY_URL` | `01`のステップ6で控えたFunction URL（末尾 `/` まで） | `https://abc123….lambda-url.ap-northeast-1.on.aws/` |
| `RELAY_KEY` | 合鍵①（AWSのLambda環境変数と**完全に同じ**） | （32桁以上） |
| `ADMIN_OP_KEY` | 合鍵②（AWSのLambda環境変数と**完全に同じ**） | （32桁以上・①と別） |
| `RELAY_PROXY` | 社内プロキシ | `10.33.2.33:8080` |
| `ADMIN_PASSWORD` | 管理画面のログインパスワード（人が打つ） | （覚えにくい文字列） |

> 💡 **コピペ必須**。RELAY_KEY / ADMIN_OP_KEY は1文字でも違うと `unauthorized` / `admin_forbidden` になります。
> AWSに入れた値と、ここに入れる値は、必ず**同じ元テキストからコピペ**してください。

3. **文字コード「UTF-8（BOMなし）」で保存**する。
   - おすすめ：**VSCode**（右下の文字コード表示をクリック→「エンコード付き保存」→ **`UTF-8`**。VSCodeの「UTF-8」はBOMなし）。
     または**秀丸**（保存時にエンコードで **`UTF-8(BOM無)`** を選ぶ）。
   - ⚠️ **古いWindowsのメモ帳は使わない**：メモ帳の「UTF-8」は**BOM付き**になりがちで、include先頭に見えない文字が入り
     **500エラーや文字化け**の原因になります（`kb_config.asp` と `kb_lib.asp` は他ファイルに読み込まれるため特に危険）。
   - ⚠️ Shift-JIS等で保存しても文字化け・500になります。**必ず UTF-8（BOMなし）**。

✅ こうなれば成功：`kb_config.asp` の中の `XXXX` / `REPLACE_*` が、すべて本物の値に置き換わっている。

---

## ステップ2. すべてのASPファイルもUTF-8で用意

`kb_lib.asp` / `kb_register.asp` / `kb_ask.asp` / `kb_admin.asp` / `kb_bulk.asp` も、**UTF-8（BOMなし）** であることを確認します。
このリポジトリのファイルは元からUTF-8です。エディタで開いて別名保存し直す場合も、文字コードをUTF-8のままにしてください。

---

## ステップ3. munu にアップロードする

1. munu の **`…/tacit2/`** フォルダへ、次の**6ファイル**を置く：
   - `kb_config.asp`（本物）
   - `kb_lib.asp`
   - `kb_register.asp`
   - `kb_ask.asp`
   - `kb_admin.asp`
   - `kb_bulk.asp`
2. `kb_config.example.asp` は**置かなくてよい**（見本なので。置いても害はない）。

> 🔒 **`kb_config.asp` の扱い**：これは合鍵入りの秘密ファイルです。
> - GitHub等に上げない（このリポジトリでは `.gitignore` 済み）。
> - 可能なら Webルート外に置いて include するのが理想（`docs/routeb_design.md §7`）。まずは `tacit2/` 内でも可。

✅ こうなれば成功：`tacit2/` に6ファイルが並んでいる。

---

## ステップ4. ブラウザで動作確認

社内ネットワークのPCから、munuのページを開きます（URLは引き継ぎ資料のもの）。

1. **登録：** `http://www.hanbai.mint.go.jp/tacit2/kb_register.asp`
   - 上部に「🔧 接続設定が未完了です」が**出ていない**ことを確認。
   - 出ている場合 → `kb_config.asp` の `RELAY_URL` / `RELAY_KEY` がまだ見本のまま（`XXXX`/`REPLACE_`）。ステップ1をやり直す。
   - テスト登録：タイトルと本文を入れて「登録する」→ **「登録できました🎉（受付ID: …）」** が出れば成功。

2. **質問：** `http://www.hanbai.mint.go.jp/tacit2/kb_ask.asp`
   - 「テストです」と質問 → 数秒待って**AIの回答が表示**されれば成功。
   - （さっき登録した内容について聞くと、数分後の同期後に反映されます）

3. **管理：** `http://www.hanbai.mint.go.jp/tacit2/kb_admin.asp`
   - `ADMIN_PASSWORD` でログイン → **一覧が表示**されれば成功（一覧には「種別（公式/暗黙知）」列があります）。
   - 1件「編集」→保存、または「削除」を試し、**「✅ …しました」** が出れば、管理opのサーバ側認可（ADMIN_OP_KEY）まで通っています。

4. **公式一括投入：** `http://www.hanbai.mint.go.jp/tacit2/kb_bulk.asp`（管理画面から「公式一括投入」でも入れます）
   - `ADMIN_PASSWORD` でログイン → `.md`/`.txt` を数件選び、プレビュー表が出れば読み取りOK。
   - 「この内容で公式登録する」→ **「✅ N/N 件を登録・更新しました」** が出れば、`register_bulk`（ADMIN_OP_KEY）まで通っています。
   - 同じファイル名で再投入すると **🔁 更新**（重複せず上書き）になることも確認できます。

✅ こうなれば成功：登録・質問・管理・公式一括投入の4画面がすべて動く。

## うまくいかないとき（よくある3つ）

| 症状 | ほぼこの原因 | 直し方 |
|---|---|---|
| 画面に「接続設定が未完了です」 | `kb_config.asp` が見本のまま | `RELAY_URL`/`RELAY_KEY`/`ADMIN_OP_KEY` を本物に。UTF-8保存 |
| 登録/質問が「認証に失敗（unauthorized）」 | RELAY_KEY がAWSと不一致 | 両方を同じ元からコピペし直す |
| 管理の編集/削除が「admin_forbidden」 | ADMIN_OP_KEY がAWSと不一致 | 両方を同じ元からコピペし直す |
| 「接続エラー」で止まる | プロキシ未設定/誤り | `RELAY_PROXY = "10.33.2.33:8080"` を確認 |
| 日本語が文字化け/500 | UTF-8で保存されていない | 全ASPを UTF-8（BOMなし）で保存し直す |

さらに詳しくは **`05_verify_troubleshoot.md`**。
