# 08 画像・図も回答に含める（高度な解析／FMパーサ）

投入した資料の中の **図・写真・スクリーンショット・スキャンされた文字** を、AIが“見て”内容を読み取り、
**回答に反映**できるようにする追加設定です。

> この手順は、すでに **07（本番構築）で KB・データソースを作り終えている前提**の「追い足し」です。
> コード改修は不要で、**AWS（Bedrock）側の設定変更＋再同期**だけで有効になります。

---

## 0. 先に押さえる3つのルール（重要）

1. **画像を読めるのは「PDF」です。** 図・画像を含む **Word/Excel は、PDFに書き出してから投入**してください。
   Word/Excel を直接入れると **文字だけ**が取り込まれ、貼り付けた図・スクショ・写真の中身は伝わりません。
2. 回答に出るのは「画像の **内容を説明した文章**」です（画像そのものが回答欄に表示されるわけではありません）。
   例：「構成図によると機器Aは…」「画面キャプチャのエラーコードは…」のように、**図から読み取った情報が文章で返ります**。
3. 高度な解析は **取り込み時にページ単位で課金**（質問のたびではない）。**図が重要な資料だけ** PDF化して入れるのが無駄がありません。

> 🔒 セキュリティ：画像の解析も **Bedrock内（Claude）で完結**します。外部のOCRサービスには出ず、学習にも使われません。
> ＝**今の安全境界（4関門）のまま**、画像認識だけを足せます。

---

## 1. 高度な解析を有効化する手順（大阪リージョン ap-northeast-3）

0. AWSにログインし、画面右上のリージョンが **「アジアパシフィック（大阪）ap-northeast-3」** になっていることを確認。
1. **Bedrock** → 左メニュー **「ナレッジベース（Knowledge Bases）」** → **`munu-tacit-kb`** を開く。
2. 「データソース」欄の **`munu-docs`** を選び、**［編集（Edit）］**。
3. **「解析（Parsing configuration）」** の項目で、既定（テキスト抽出）から
   **「Foundation models for parsing（高度な解析）」に切り替える**。
   - 解析に使う **モデルを選択**（大阪で使えるものが一覧に出ます）。
     - ▶ **一覧に何も出ない／選べない場合**は、そのモデルの **アクセスを有効化**してから戻る
       （Bedrock →「モデルアクセス」または「モデルカタログ」で対象モデルを有効化。**07のステップ①と同じ要領**）。
   - （任意）**解析の指示（プロンプト）** を入れられる欄があれば、
     「**図・表・スクリーンショット内の文字と数値も漏れなく書き出す。日本語で。**」等を指定すると精度が上がります。
4. **［保存／更新（Save）］**。
5. **再同期（Sync）＝ここが肝心**：`munu-docs` の画面で **［同期（Sync）］** を押す。
   完了まで数分〜。これで**今後**投入するPDFは高度な解析で取り込まれます。

✅ こうなれば成功：`munu-docs` の解析が「Foundation models for parsing」になり、同期が「完了（Completed）」。

> 📌 **すでに入れてある資料も画像を読ませたい場合**：そのファイルを **PDFにして、同じファイル名（識別子）で「公式一括投入」から再投入**してください。
> 同名＝**上書き（更新）**なので、高度な解析で取り込み直されます（このシステムの上書き機能をそのまま利用）。

---

## ⚠️ 1-B. 「解析戦略」が Default のまま変えられない場合（データソースの再作成）

編集画面で **「解析戦略：Default」が文字表示だけ**で基盤モデルに変えられない
（＝Bedrockは**解析・チャンキング戦略をデータソース作成時に固定**することがある）場合は、
**新しいデータソースを作り直す**のが確実です。**KB本体（`munu-tacit-kb`）は作り直し不要**。

1. まず **「詳細設定（Advanced settings）- オプション」** の ▶ を開き、解析戦略を
   **「基盤モデルを使用した解析／Foundation models」に変えられるか**を確認。変えられれば手順1でOK（再作成不要）。
2. 変えられない場合 → 同じKBの「データソース」で **［データソースを追加（Add data source）］**：
   - 名前：`munu-docs2`（任意）
   - **S3 URI：既存とまったく同じ** `s3://mint-tacit-kb/tacit/`
   - **「S3データ用のカスタマーマネージドKMSキーを追加」：今の `munu-docs` と同じく“チェックしない”**
     （現構成はKBのサービスロールにKMS復号権限があり、チェック無しで読めています。既知の正常設定に合わせる）。
     　▶ もし後の同期で **KMS/アクセス系のエラー** が出たら、その時だけチェックを入れて `alias/munu-kb` を指定。
   - **解析戦略：高度な解析（Foundation models）** ＋ 解析モデルを選択 ←**今回の目的（唯一の変更点）**
   - チャンキング：既存と同じ（通常はデフォルト）
   > ⚠️ 作成した直後は**まだ同期しない**（旧 `munu-docs` を消す前に同期すると、同じS3を二重取り込みするため）。
3. 作成後、**新しい「Data source ID」をコピー**。
4. **Lambdaの環境変数 `DATA_SOURCE_ID` を新しいIDに更新** ＆ **台帳も更新**（`KB_ID` は変更なし）。
5. **古い `munu-docs`（Default解析）は削除**する。
   ※同じS3を指すデータソースが2つ残ると **重複取り込み** になるため、必ず片方に。
6. 新しいデータソースで **同期（Sync）**。

> ✅ これで以後の投入はすべて高度な解析で取り込まれます。既存資料はPDF化して同名で再投入すれば反映されます。
> ⚠️ `DATA_SOURCE_ID` の更新を忘れると、Lambdaが**古い（削除した）データソースを同期しようとしてエラー**になります。必ず差し替えを。

---

## 2. ちゃんと効いているかの確認

1. **図・スクショを含む資料を PDF で保存** → 管理画面の **「公式一括投入」** から投入（数分待つ）。
2. 質問画面で、**その図の中にしか無い情報**を質問する
   （例：構成図の機器名／画面の数値／エラーコード／表のセルの値 など）。
3. 回答にその内容が出れば **成功**。テキストには書いていない＝画像から読めた、という確認になります。

---

## 3. うまくいかない時

| 症状 | 原因 / 対処 |
|---|---|
| 画像の内容が回答に出ない | ① 解析が**既定のまま** → 手順1-3を再確認 ② **同期し直す**（手順1-5） ③ 画像入り**PDF**で入れたか（**Word/Excel直接はNG**、PDFに書き出す） |
| 既存資料だけ反映されない | PDFにして **同じファイル名で再投入**（上書き＝再解析） |
| 解析用モデルが選べない | 大阪でそのモデルが**未解禁** → モデルアクセスを有効化（手順1-3の▶） |
| 図は読めるが不正確 | 複雑な図・極小文字・手書きは苦手。**重要な数値・用語は本文テキストにも併記**して投入すると確実 |
| コストが気になる | 高度な解析は**取り込み時のページ課金**。**図が要る資料だけ**PDF化。テキスト主体の資料は従来どおり（既定）でOK |

## ⚠️ 3-B. 解析モデルで同期が失敗する（モデルアクセス／KBロール権限）

高度な解析を有効にして同期すると、こんなエラーが出ることがあります：

> `Knowledge base role ... is not able to call the specified model ... Model access is denied ... (aws-marketplace:Subscribe) ...`

意味：**KBのサービスロールが、解析用に選んだ基盤モデル（例：Claude Sonnet 4.5）を呼べない**。
原因は2つあり、**両方**を満たす必要があります。

**① 解析モデルの「モデルアクセス」を有効化（アカウント単位）**
- Bedrock（**大阪 ap-northeast-3**）→「モデルカタログ／モデルアクセス」で、**選んだ解析モデル（例：Claude Sonnet 4.5）を有効化**。
- 反映に数分（エラーにも「2分後に再試行」とある）。→ 有効化後に**もう一度［同期］**。

**② KBサービスロールに「InvokeModel」権限を足す**
- ①だけで直らない場合、KBロールに解析モデルを呼ぶ権限が無い。
- IAM →「ロール」→ エラーに出ている **KBロール**（例：`AmazonBedrockExecutionRoleForKnowledgeBase_xxxx`）→
  「許可を追加」→「インラインポリシーを作成」→ JSON に以下を貼る（**ARNは自分のアカウント/リージョン/モデルに合わせる**）：

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "KbAdvancedParsingInvokeModel",
    "Effect": "Allow",
    "Action": ["bedrock:InvokeModel", "bedrock:InvokeModelWithResponseStream"],
    "Resource": [
      "arn:aws:bedrock:ap-northeast-3:＜アカウントID＞:inference-profile/jp.anthropic.claude-sonnet-4-5-20250929-v1:0",
      "arn:aws:bedrock:ap-northeast-1::foundation-model/anthropic.claude-sonnet-4-5-20250929-v1:0",
      "arn:aws:bedrock:ap-northeast-2::foundation-model/anthropic.claude-sonnet-4-5-20250929-v1:0",
      "arn:aws:bedrock:ap-northeast-3::foundation-model/anthropic.claude-sonnet-4-5-20250929-v1:0"
    ]
  }]
}
```
- 保存 → 2分ほど待って **再度［同期］**。

> 📌 これは **Lambdaの実行ロールではなく、KB（ナレッジベース）のサービスロール**への追加です。混同注意。
> 💡 待ち時間を避けたいなら、解析モデルに**すでに有効化済みのモデル（例：回答用のClaude Haiku 4.5）**を使う手も
> （①が不要に。②のInvokeModel権限は同様に付与）。ただし複雑な図は上位モデルの方が正確です。

---

## 4. コストの考え方（目安）

- 高度な解析の費用は **「取り込み（同期）した時に1回だけ」** ページ単位で発生します（質問のたびではありません）。
- したがって **大量の画像PDFを一気に入れる**と取り込み費用がかさみます。**重要な設計書から少しずつ**が安全。
- テキスト主体の資料は、無理に高度な解析へ回さず**既定（テキスト抽出）**のままで十分です。

> 💡 運用のコツ：普段のマニュアルは今まで通り。**「図を見ないと分からない資料」だけ PDF＋高度な解析** に回す——
> これが精度・コストの両面でいちばん効率的です。
