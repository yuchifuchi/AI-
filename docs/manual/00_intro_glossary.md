# 00 はじめに ＋ 用語集（まずここを読む）

このマニュアルは、**AWSもプログラムもよく知らない人**でも、順番どおりにやれば
セキュリティ改修（Route B）を設定できるように書いています。
専門用語は初回に必ずカッコで説明します。分からない言葉が出たら、この用語集に戻ってください。

---

## 0-1. これから何をするの？（3行で）

1. いまのシステムは「**誰でも開ける公開の郵便受け（公開S3バケット）**」を使っていて危険、と診断されました。
2. そこで「**鍵つきの窓口（認証つきのURL）**」に付け替えます。これが **Route B** です。
3. 付け替えると、**社内の合鍵（秘密の文字列）を持ったmunuだけ**が窓口を使えるようになります。

絵にすると：

```
【改修前】あぶない
  みんな → 公開の郵便受け(誰でも投函/中身も条件次第で読める) → AI

【改修後（Route B）】あんしん
  munu → 鍵つき窓口(合鍵が合う人だけ) → AI
         （郵便受けそのものを撤去する）
```

## 0-4. これから新しく作る「3つの秘密」

Route B では、次の3つの秘密の文字列を使います。**紙やチャットに貼らず**、パスワード管理ソフト等に保管してください。

| 名前 | 何に使う | 長さの目安 | どこに設定するか |
|---|---|---|---|
| **RELAY_KEY** | munu→窓口の「合鍵」。これが合う人だけ窓口を使える | 32文字以上のランダム英数字 | AWS(Lambda環境変数) と munu(kb_config.asp) の**両方に同じ値** |
| **ADMIN_OP_KEY** | 管理操作（編集・削除）専用の第2の合鍵 | 32文字以上・RELAY_KEYとは別の値 | AWS(Lambda環境変数) と munu(kb_config.asp) の**両方に同じ値** |
| **ADMIN_PASSWORD** | 管理画面 log in の入口パスワード（人が打つ） | 覚えにくく破られにくいもの | munu(kb_config.asp) だけ |

> **鍵の作り方（かんたん）**：Windowsの「PowerShell」を開いて、次を打つとランダムな32桁が出ます。
> ```powershell
> [guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N")
> ```
> 出た文字列をコピーして保管。RELAY_KEY と ADMIN_OP_KEY は**別々に**作ってください（2回実行）。

## 0-5. 用語集（知らない言葉が出たらここ）

| 言葉 | やさしい意味 |
|---|---|
| **AWS** | Amazon が貸してくれるクラウド（インターネットの向こうにあるコンピュータ群）。 |
| **リージョン** | AWSの「地域」。ここでは東京（ap-northeast-1）を使う。データが日本国内に留まる。 |
| **S3バケット** | AWS上の「ファイル置き場」。バケット＝箱。 |
| **公開バケット / 非公開バケット** | 公開＝設定次第で外から読める箱。非公開＝許可された人（プログラム）だけが読める箱。今回は**非公開にする**。 |
| **Block Public Access（BPA）** | バケットを「公開にできないよう固くロックする」スイッチ。**ON＝安全**。 |
| **Lambda** | サーバを自分で用意せずに動かせる小さなプログラム。今回の「窓口の中の人」。 |
| **Function URL** | その Lambda を呼び出すための **専用URL**（https://…on.aws/）。今回の「窓口の住所」。 |
| **認証タイプ NONE** | Function URL 自体は誰でも叩ける設定。ただし**中の人(Lambda)が合鍵(X-Relay-Key)を確認**するので、鍵が無ければ門前払い。 |
| **ヘッダ / X-Relay-Key** | HTTP通信に付ける「付箋」。合鍵をこの付箋に書いて渡す。URLに書かないのでログに残らない。 |
| **IAM / 実行ロール** | AWSの「権限の割り当て」。Lambdaに「このバケットだけ触ってよい」と最小限の許可を与える。 |
| **バケットポリシー** | バケットに貼る「入館ルール」。今回は「暗号化通信(TLS)以外お断り」「アカウント外お断り」を書く。 |
| **Bedrock / Knowledge Base(KB)** | AWSの生成AI基盤と、その「社内資料の検索データベース」。今回は既存のものをそのまま使う。 |
| **プロキシ** | 社内から外に出るときに通る「関所」。`10.33.2.33:8080`。munuはここを通って窓口に届く。 |
| **CSRF** | 利用者をだまして意図しない操作をさせる攻撃。対策の「合言葉(トークン)」をフォームに仕込む。 |
| **監査ログ** | 「誰が・いつ・何をしたか」の記録。CloudWatch（AWSのログ置き場）に残す。 |
| **CloudWatch** | AWSのログ／監視の画面。Lambdaの動作記録やエラーがここに出る。 |
| **機微度（sensitivity）** | 文書の「見せてよい範囲」の度合い。low(誰でも)/mid(社内)/high(機微)。 |
| **フェイルオープン / フェイルクローズ** | 設定ミス時に「開いてしまう(危険)」か「閉じる(安全)」か。今回は閉じる側に倒す。 |
