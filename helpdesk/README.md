# 類似案件サジェスト ── ヘルプデスク台帳（Access + classic ASP）

**新規案件を入力している最中に、過去の似た案件が横に勝手に出る**仕組みです。
利用者は検索操作をしません。これが「検索窓」と決定的に違う点です。

AIもクラウドも使いません。**追加費用はゼロ**です。

---

## ファイル

| ファイル | 役割 |
|---|---|
| `hd_config.example.asp` | 接続先とフィールド名の設定（見本）。コピーして `hd_config.asp` を作る |
| `hd_similar.asp` | 検索して JSON を返すAPI。画面は持たない |
| `hd_similar_embed.html` | 登録画面に貼り付ける HTML + JS + CSS |

---

## 導入手順

### 1. ファイルを置く
既存のヘルプデスクASPと**同じフォルダ**に `hd_similar.asp` と `hd_config.asp` を置きます。

### 2. `hd_config.asp` を実物に合わせる
`hd_config.example.asp` をコピーし、★の付いた箇所を書き換えます。

- `HD_CONN` … .accdb のパス。**wwwroot の外に置いてください**（URL直打ちで丸ごと落とされます）
- `HD_TABLE` / `HD_COL_*` … 実際のテーブル名・列名
- `HD_COL_CAT` … 分類の列が無ければ `""` にする（表示から消えます）

### 3. 登録画面にスニペットを貼る
`hd_similar_embed.html` の中身を、登録フォームの**横または下**に貼り付けます。
貼ったあと、JS冒頭の2箇所を実物に合わせます。

```js
var HD_WATCH = ["#件名", "#問い合わせ内容"];   // 監視する入力欄のセレクタ
var HD_DETAIL_URL = "台帳詳細.asp?id=";        // 詳細画面のURL（不要なら ""）
```

> `#件名` は `id="件名"` を指します。実際のフォームが `name` しか持っていない場合は
> `["[name='subject']", "[name='body']"]` のように書けます。

### 4. 動作確認
登録画面で問い合わせ内容を4文字以上入力し、**0.6秒待つ**と候補が出ます。
出ない場合は下の「うまくいかないとき」へ。

### 5. （推奨）同義語テーブルを作る
無くても動きますが、**あると精度が大きく変わります**。次項参照。

---

## 同義語テーブル（ここが精度の要）

Accessに次の2列のテーブルを1つ作ります。

| テーブル名 | 列 | 型 |
|---|---|---|
| `同義語` | `語` | 短いテキスト |
| | `言い換え` | 長いテキスト（`,` または `、` 区切り） |

### 初期データの例

| 語 | 言い換え |
|---|---|
| プリンタ | プリンター、印刷、複合機、コピー機、出力 |
| ログイン | サインイン、入れない、パスワード、認証 |
| メール | Outlook、送信、受信、添付 |
| 共有フォルダ | ファイルサーバ、ネットワークドライブ、Zドライブ |
| 起動 | 立ち上がらない、電源、フリーズ、固まる |

**この表に載っている語のどれかが入力に含まれていれば、同じ行の語すべてで検索します。**
「プリンターが動かない」と入力しても、「印刷できない」と書かれた過去案件が見つかります。

### なぜこれが効くのか

AIの「意味で探す」能力の代わりを、辞書が果たします。AIと違って
**なぜヒットしたかが説明でき、外した時に直せます。** そして
**使うほど賢くなります**（下記）。

### 育て方（重要）

**「候補が出なかった入力」を記録して、月に一度、辞書に足してください。**
これが唯一のメンテナンス作業で、これをやるかどうかで価値が決まります。

記録の実装は含めていません（Accessへの書き込みは同時実行に弱いため、
テキストファイルへの追記を推奨します）。必要でしたら追加します。

## 日本語をどう切っているか

形態素解析エンジンは導入できないので、3段構えにしています。

| 段 | 方法 | 何を拾うか |
|---|---|---|
| 1 | 同義語辞書との照合 | 「印刷設定画面」から「印刷」を拾える。**連結語に強い** |
| 2 | 正規表現で漢字・カタカナ・英数字の連続を抽出 | 型番・画面ID・固有名詞。辞書に無い語 |
| 3 | 語が2個以下の時だけ、連結語を2文字ずつに分割 | 保険 |

2段目が成立するのは、**日本語では助詞と活用がひらがなで書かれる**ためです。
漢字・カタカナ・英数字の連続だけを取れば、名詞がおおむね拾えます。

得点は **件名に一致=3点 / 問い合わせ内容=1点 / 対応内容=1点**。
件名に出る語のほうが本題を表しているため、重く見ています。

## 性能の目安

`LIKE '%語%'` はインデックスが効きません。**全件走査**になります。

| 台帳の件数 | 体感 |
|---|---|
| 〜5,000件 | 一瞬（0.1秒未満） |
| 〜50,000件 | 問題なし |
| 100,000件〜 | 遅さを感じ始める |

遅くなったら `hd_config.asp` の `HD_YEARS` を `3` などにして、
**直近3年だけを検索対象**にしてください。実務上ほぼ影響ありません。

---

## うまくいかないとき

| 症状 | 確認 |
|---|---|
| 候補が1件も出ない | `HD_WILDCARD` を `"%"` → `"*"` に変える。接続モードで異なります |
| `db_open_failed` が返る | .accdb のパス、IISアプリプールのアカウントにフォルダの読み書き権限があるか。ACEのビット数とアプリプールのビット数が一致しているか |
| `query_failed` が返る | テーブル名・列名の綴り。`ORDER BY sc` が通らない場合は、得点式を `ORDER BY` にも書き写す |
| 何も反応しない | ブラウザの開発者ツール（F12）でJSエラーを確認。`HD_WATCH` のセレクタが実物と合っているか |
| 関係ない案件ばかり出る | 同義語テーブルを作る。汎用的すぎる語（「対応」「確認」など）は辞書に入れない |

## 制約（正直に）

- **言い換えは辞書に書いた分しか効きません。** AIのように未知の言い換えは吸収しません
- **会話形式の追い質問はできません**。1回の入力に対する候補提示のみ
- **PDF・Word の中身は検索しません**。台帳のテキスト列だけが対象です
- Access Database Engine は 2025年10月にサポート終了済みです。動作しますが、
  サーバ更改時に問題化する可能性があります（実体を SQL Server Express や
  SQLite に移し、Accessからリンクテーブルで見る形にすれば回避できます）

---

## この仕組みの位置づけ

これは**「AIの安い代替品」ではありません。**

AIナレッジ検索には「誰かが自発的に登録しないと中身が増えない」という
構造的な弱点がありました。ヘルプデスク台帳は、
**問い合わせ対応をすれば業務の副産物として自動的に記録が貯まります。**

まずこの形で「役に立った／立たなかった」を確かめ、
「言い換えに弱い」「要約が欲しい」という不満が具体的に出てきた段階で、
はじめてAIを足すのが順序として妥当だと考えます。
